# webview-qr-scanner

Сканер QR-кодов и штрихкодов с камеры, который работает внутри Telegram WebView (iOS/Android) и в iOS Safari. ZBar WASM, ~355 КБ, без зависимостей, без сборки.

Он читает QR-коды и линейные штрихкоды с основной камеры и отдаёт вам сырой текст и название
типа кода. Он сделан для мест, где браузерные сканеры обычно ломаются: Telegram Mini App,
встроенный браузер Telegram, iOS Safari. Его настройки по умолчанию пришли из production-проекта
с живыми пользователями, и раздел [Почему это работает](#почему-это-работает) объясняет каждую.

English version: [README.md](README.md)

## Что это

- **Ядро сканера**, `src/cam-scanner.js`: открывает камеру, отдаёт кадры в ZBar, вызывает ваш
  колбэк с `(text, type)`. Цифровой зум, защита от повторов, пауза и продолжение, фонарик,
  корректная остановка.
- **ZBar, скомпилированный в WebAssembly**: `wasm/zbar.wasm` (338 КБ) и его загрузчик
  Emscripten `wasm/zbar.js` (15 КБ), взяты без изменений из проекта
  [koder](https://github.com/maslick/koder). Небольшая связка между ZBar и сканером встроена в
  `src/cam-scanner.js`.
- **Необязательные парсеры** в `src/parsers/`. Первый из них — `FnsReceipt`: он превращает
  QR-код с российского кассового чека (ФНС) в поля.
- **Без зависимостей, без сборки, без фреймворка.** Ядро и парсеры написаны на обычном ES5
  (поставляемый связующий код Emscripten использует возможности ES2015 в пределах заявленных
  версий движков); вы кладёте файлы рядом со своей страницей и подключаете их тегами `<script>`.
  Одинаково работают в Telegram Mini App, на обычном сайте и в WebView внутри нативного
  приложения.

Для кого: для разработчиков, которым внутри Mini App или мобильной веб-страницы нужно «навёл
телефон на код — получил текст», и которые уже пробовали библиотеку-сканер, работавшую на
компьютере и отказавшую на телефоне.

## Подключение

1. Скопируйте папки `wasm/` и `src/` из этого репозитория рядом со своей страницей
   (`git clone https://github.com/mad8fat/webview-qr-scanner` или скачайте ZIP).
2. Подключите скрипты в этом порядке и создайте сканер:

```html
<div style="width: 100%; max-width: 480px; aspect-ratio: 4 / 3; overflow: hidden;">
  <video id="cam" playsinline muted style="width: 100%; height: 100%; object-fit: cover;"></video>
</div>

<script src="wasm/zbar.js?v=0.1.0"></script>
<script src="src/cam-scanner.js?v=0.1.0"></script>
<script>
  var scanner = CamScanner.create({
    video: document.getElementById('cam'),
    wasmDir: 'wasm',
    onCode: function (text, type) { console.log(type, text); },
    onError: function (err) { console.log(err.code, err.message); }
  });
  scanner.start();
  window.addEventListener('pagehide', function () { scanner.stop(); });
</script>
```

- **Порядок подключения важен:** `wasm/zbar.js` → `src/cam-scanner.js`
  (→ `src/parsers/fns-receipt.js`, если он нужен). `zbar.js` должен идти первым: он объявляет
  глобальную `CreateKoder`, через которую ядро запускает ZBar.
- **`wasmDir`** должен указывать на папку, где лежит `zbar.wasm`: относительно страницы или
  абсолютным URL. Ядру нужны только два файла из `wasm/`: `zbar.js` (подключается вашим тегом
  `<script>`) и `zbar.wasm` (загружается из `wasmDir`). При раскладке выше это `'wasm'`; со страницы во вложенной папке — `'../wasm'`.
  Для каждого `wasmDir` WASM загружается один раз на страницу: каждый следующий сканер
  (например, после смены камеры) использует уже загруженный.
- **Обёртка с `overflow: hidden`** держит визуальный зум (CSS `scale()` на видео) внутри своей
  рамки.
- **`?v=0.1.0` у каждого скрипта** обходит кэш Telegram WebView: Telegram долго держит старые
  скрипты, поэтому поднимайте версию в каждом релизе. `zbar.wasm` запрашивается из `zbar.js` под
  фиксированным именем, поэтому если вы когда-нибудь замените ZBar (всегда `zbar.wasm` и
  `zbar.js` вместе), положите новые файлы в новую папку, поменяйте `wasmDir` и поднимите `?v=` у
  `zbar.js`.

### Требования

- **Защищённый контекст: HTTPS или `localhost` / `127.0.0.1`.** Браузеры дают доступ к камере
  только защищённым страницам; адреса локальной машины — исключение, что удобно при разработке.
- **`Content-Type: application/wasm`** для `zbar.wasm`. Без него браузер отказывается от
  потоковой компиляции, связующий код пишет ошибку в консоль и переходит на более медленный путь.
  Большинство серверов уже отдают правильный тип; проверьте командой
  `curl -sI https://your.site/wasm/zbar.wasm`.
- **Если у вас есть Content Security Policy**, `script-src` должен разрешать WebAssembly:
  `'wasm-unsafe-eval'` в Chrome 97+ / Safari 16+, `'unsafe-eval'` в более старых движках.
- **Движки:** Chrome / Android WebView ≥ 57, Safari / iOS ≥ 11 (WebAssembly); WKWebView
  (Telegram iOS, встроенные браузеры приложений) — iOS ≥ 14.3 для `getUserMedia`; WebView внутри
  вашего собственного нативного приложения должен выдать доступ к камере (Android —
  `onPermissionRequest` и разрешение CAMERA, iOS — `NSCameraUsageDescription`).

## API

### `CamScanner.create(options)` → сканер

Бросает `TypeError`, если не передан `options.video`. До вызова `start()` больше ничего не
происходит.

| Опция | По умолчанию | Значение |
|---|---|---|
| `video` | (обязательна) | Элемент `<video>`, в котором показывается камера. Ядро само ставит ему `playsinline`, `muted` и `autoplay`. |
| `wasmDir` | `'wasm'` | Папка, в которой лежит `zbar.wasm` (завершающие слэши не важны). Для каждого `wasmDir` WASM загружается один раз на страницу и общий для всех сканеров с этой папкой. |
| `zoom` | `2` | Коэффициент цифрового зума: декодер видит центральную часть кадра размером `1/zoom`. Значение, не являющееся положительным числом, превращается в `1`. |
| `visualZoom` | `true` | Также увеличивать `<video>` через CSS `transform: scale(zoom)`, чтобы пользователь видел то же, что и декодер. Перезаписывает `transform` элемента `<video>`: чтобы сохранить свой (например, зеркало), задайте `visualZoom: false` и масштабируйте видео сами. |
| `dedupeMs` | `0` | `0`: один и тот же текст сообщается один раз, пока вы не сбросите защиту от повторов. `> 0`: тот же текст сообщается снова, если он не распознавался столько миллисекунд. |
| `constraints` | встроенные | Ваши собственные ограничения `getUserMedia` для первого запроса камеры, в полном виде, например `{ video: { deviceId: { exact: id }, width: { ideal: 1920 }, height: { ideal: 1080 } } }`. Они ЗАМЕНЯЮТ встроенные ограничения целиком (ничего не объединяется, поэтому разрешение запрашивайте сами). Если такой запрос не удался, ядро молча переходит на свои встроенные мягкие ограничения (основная камера), кроме случая, когда в доступе отказано. |
| `formats` | | Зарезервировано, не используется: ZBar читает все известные ему форматы. Фильтруйте по `type` в `onCode`. |
| `torch` | `false` | Попытаться включить фонарик сразу после начала сканирования (экспериментально, см. ниже). |
| `onCode(text, type)` | | Распознан код. `text` — сырая строка, `type` — название типа кода в ZBar, например `'QR-Code'` или `'EAN-13'`. |
| `onStatus(state)` | | Изменилось состояние (см. ниже). |
| `onError(error)` | | Что-то пошло не так: `{ code, message, cause }`. |
| `env` | глобальные | Точка подмены для тестов: объект, заменяющий глобальные объекты браузера (`navigator`, `document`, `requestAnimationFrame`, `cancelAnimationFrame`, `setTimeout`), фабрику ZBar `CreateKoder` (обычно это глобальная из `zbar.js`) и обёртку декодера `Koder`. Нужен юнит-тестам, чтобы запускать ядро в Node с подделками; обычно вы его не передаёте. Переданные `CreateKoder` или `Koder` не делятся между сканерами. |

Исключение, брошенное внутри `onStatus` или `onError`, не ломает сканер (оно пробрасывается
асинхронно). Исключение, брошенное внутри `onCode`, приходит в `onError` с кодом `decode`.

### Методы

| Метод | Что делает |
|---|---|
| `start()` → `Promise` | Загружает WASM, запрашивает камеру, начинает сканирование. Промис **никогда не отклоняется**: все сбои приходят в `onError`. Вызов, пока сканер запускается или работает, возвращает тот же промис. После `stop()` можно вызвать снова. |
| `pause()` | Останавливает распознавание (только из `scanning`). Камера и видео продолжают работать, поэтому продолжение мгновенное. |
| `resume(options)` | Продолжает распознавание из `paused` (или `scanning`). Вызывает `video.play()`, если видео стояло на паузе. `resume({ resetDedupe: true })` вдобавок забывает последний код. |
| `resetDedupe()` | Забывает последний код, чтобы тот же код можно было сообщить снова. |
| `stop()` → `Promise` | Выключает фонарик (ждёт этого не дольше 300 мс), отменяет цикл кадров, останавливает все треки камеры и отвязывает поток. Никогда не бросает исключений. Промис разрешается, когда камера освобождена. |
| `setZoom(level)` | Сразу меняет цифровой зум (и визуальный, если он включён). |
| `setTorch(on)` → `Promise` | Разрешается в `'on'`, `'off'` или `'unsupported'` (см. пункт 4 в разделе [Почему это работает](#почему-это-работает)). Экспериментально, в production не проверено. |
| `getState()` | Текущее состояние. |

### Состояния

`idle` → `loading-wasm` → `requesting-camera` → `scanning` ⇄ `paused` → `stopped`

- `idle`: создан, ещё не запущен; также состояние после неудачного запуска и после завершения
  трека камеры.
- `stopped`: после `stop()`; отсюда снова работает `start()`.
- Когда запуск не удался, состояние сначала возвращается в `idle`, а затем вызывается `onError`.

### Коды ошибок

| `code` | Когда |
|---|---|
| `wasm` | ZBar не загрузился: `zbar.js` не подключён до `start()` (`CreateKoder not found`), неверный `wasmDir`, нет `zbar.wasm`, заблокирован CSP. |
| `camera` | Нет камеры, в доступе отказано, камера занята или видео не удалось подключить. А также `message: 'video.play() rejected'`, когда браузер отказался запускать видео (см. пункт 7 в разделе [Почему это работает](#почему-это-работает)); в этом случае состояние остаётся `scanning`. А также `message: 'camera track ended'`, когда трек камеры завершился во время работы сканера (камеру забрало другое приложение, отозвано разрешение, камеру отключили): состояние переходит в `idle`, камера освобождается, а `start()` (кнопка «Попробовать снова») открывает её заново. |
| `decode` | Исключение при обработке кадра, в том числе брошенное вашим `onCode`. |
| `torch` | Браузер отклонил запрос на фонарик. |

Если пользователь отказал в доступе к камере (`NotAllowedError` или `SecurityError`), ядро не
спрашивает второй раз: ошибка сразу уходит в `onError` с кодом `camera`.

### Если `video.play()` отклонён

Некоторые WebView отказываются запускать видео, которое запущено не по нажатию. Тогда ядро
сообщает `onError({ code: 'camera', message: 'video.play() rejected' })` и держит камеру
открытой. Предложите пользователю нажать: нажатие — это жест пользователя, и вызванный из него
`resume()` запускает видео:

```js
var tapButton = document.getElementById('tapToStart');

var scanner = CamScanner.create({
  video: document.getElementById('cam'),
  onCode: function (text, type) { console.log(type, text); },
  onError: function (err) {
    if (err.code === 'camera' && err.message === 'video.play() rejected') {
      tapButton.hidden = false;
    }
  }
});

tapButton.addEventListener('click', function () {
  tapButton.hidden = true;
  scanner.resume();
});

scanner.start();
```

### Показ результата: пауза, свой диалог, продолжение

```js
onCode: function (text, type) {
  scanner.pause();
  showMyDialog(text, {
    onScanMore: function () {
      showHint('Уберите код из кадра');
      setTimeout(function () { scanner.resume({ resetDedupe: true }); }, 3000);
    },
    onClose: function () { scanner.resume(); }
  });
}
```

`showMyDialog` и `showHint` — ваши собственные HTML-элементы. Никогда не используйте здесь
`alert()` или `confirm()`: см. пункт 7 в разделе [Почему это работает](#почему-это-работает).

## Парсер чека ФНС

На российских кассовых чеках печатается QR-код с данными, по которым ФНС находит чек:

```
t=20231215T1830&s=1234.56&fn=1234567890123456&i=12345&fp=1234567890&n=1
```

| Ключ | Значение | Правило (строгий режим) |
|---|---|---|
| `t` | Дата и время, `ГГГГММДДTЧЧММ`, необязательные секунды `ЧЧММСС` | Обязателен |
| `s` | Сумма чека, точка как десятичный разделитель | Обязателен, цифры с необязательной `.дробью` |
| `fn` | Номер фискального накопителя | Обязателен, ровно 16 цифр |
| `i` | Номер фискального документа (ФД) | Обязателен, 1–10 цифр |
| `fp` | Фискальный признак (ФП) | Обязателен, 1–20 цифр |
| `n` | Признак расчёта | Необязателен, отдаётся как есть |

Подключите `src/parsers/fns-receipt.js` после ядра и используйте его в `onCode`:

```js
onCode: function (text) {
  var r = FnsReceipt.parse(text);
  if (!r) { showHint('Это не QR чека'); return; }
  sendToMyBackend(r);
}
```

`FnsReceipt.parse(text)` возвращает `null` или:

```js
{
  fn: '1234567890123456',
  fd: '12345',
  fp: '1234567890',
  date: '2023-12-15',
  time: '18:30',
  amount: 1234.56,
  n: '1',
  raw: 't=20231215T1830&s=1234.56&fn=1234567890123456&i=12345&fp=1234567890&n=1'
}
```

- `fn`, `fd`, `fp` остаются строками, поэтому ведущие нули сохраняются. `amount` — `Number`.
- `n` равен `null`, если в QR-коде нет `n`.
- Параметры могут идти в любом порядке; неизвестные параметры игнорируются.
- Правила длин проверены на 18 308 реальных QR-кодах чеков: `fn` всегда был из 16 цифр, ФД — от
  1 до 10 цифр, ФП — от 6 до 14 цифр (14 встречается в чеках нового формата 1.2). Предел ФП в 20
  цифр оставляет запас сверх наблюдаемого.
- `t` проверяется **только по формату**: `20231315T9930` (13-й месяц, 99-й час) проходит. Если
  дата важна, проверяйте её сами.
- `FnsReceipt.parse(text, { strict: false })` пропускает правила длин (поля всё равно должны
  состоять из цифр) — для тех, кто проверяет чек на своём сервере.
- Когда результат `null`, `FnsReceipt.parse.lastError` объясняет причину: `empty`, `missing:fn`,
  `missing:i`, `missing:fp`, `missing:t`, `missing:s`, `bad:fn`, `bad:fd`, `bad:fp`, `bad:t`,
  `bad:s`. Обязательные поля проверяются в порядке `fn`, `i`, `fp`, `t`, `s`, поэтому обычная
  ссылка даёт `missing:fn`. После успешного разбора там `null`.

Парсер только читает QR-код. Проверка чека в ФНС — задача вашего сервера.

## Почему это работает

Каждый пункт — урок из production, кроме фонарика (пункт 4): симптом, который он лечит, и что с
этим делает ядро.

**1. Распознавание: один путь для всех платформ.**
Симптом: сканеры на браузерном `BarcodeDetector` упираются в iOS Safari, где его нет, да и в
WebView он не гарантирован; чтение канваса каждый кадр идёт медленно, когда браузер держит этот
канвас на видеокарте.
Решение: каждый кадр рисуется на скрытом `<canvas>`, созданном с `willReadFrequently: true`,
читается через `getImageData` и передаётся в ZBar на WebAssembly. Один и тот же код работает в
Chrome, Safari и любом WebView, а канвас остаётся в памяти, которую процессор читает быстро.

**2. Запрос камеры: основная камера в нормальном разрешении.**
Симптом: запрос камеры по умолчанию возвращает 640×480 или фронтальную камеру, и маленький
плотный QR-код на чеке в таком разрешении — просто серое пятно.
Решение: ядро запрашивает основную камеру (`facingMode: { exact: 'environment' }`), желательно
1920×1080 и не меньше 1280×720, 15–30 кадров в секунду, с непрерывной фокусировкой, экспозицией
и балансом белого. Если устройство не может это выполнить (у ноутбука нет основной камеры), ядро
повторяет запрос один раз с мягкими ограничениями. Если пользователь отказал в доступе, повтора
нет: второй запрос не поможет и лишь ещё раз покажет окно разрешения.

**3. Цифровой зум обрезкой кадра.**
Симптом: QR-код на чеке шириной 2–3 см. Вблизи телефон не может на нём сфокусироваться; на
расстоянии, где фокус есть, код занимает слишком мало пикселей, и ZBar его не находит. Нативный
зум камеры (`applyConstraints({ zoom })`) есть не везде и на разных телефонах ведёт себя
по-разному; в production он не прижился.
Решение: ядро увеличивает программно. При `zoom: 2` оно берёт центральную половину кадра
(ширина / 2 × высота / 2) и растягивает её на весь канвас, так что ZBar видит код вдвое крупнее
и видит меньше мусора вокруг. Пользователь держит телефон на удобном расстоянии (около 15 см),
камера фокусируется, а код всё равно достаточно крупный. `<video>` увеличивается в то же число
раз через CSS, поэтому всё, что видно на экране, распознаётся; декодер может видеть и немного
за краями. Наведите код в центр — и он прочитается. Для этого `object-fit: cover` у `<video>`
ОБЯЗАТЕЛЕН: с `contain` на экране видно больше, чем распознаётся. Визуальный зум перезаписывает
`transform` у видео; чтобы сохранить свой (зеркало), задайте `visualZoom: false` и
масштабируйте видео сами. По умолчанию `2`; `setZoom(1)` выключает зум, `setZoom(4)` — для
очень мелких кодов.

**4. Фонарик (экспериментально, в production не проверено).**
Симптом: часть Android-телефонов не объявляет `torch` в `getCapabilities()`, хотя фонарик
работает; iOS может принять запрос и ничего не сделать.
Решение: `setTorch(on)` отправляет запрос без предварительной проверки возможностей, затем
читает `getSettings().torch`. Если браузер не сообщает состояние фонарика, ядро доверяет
запрошенному состоянию и отвечает `'on'` или `'off'`. `'unsupported'` оно отвечает только при
явном расхождении (браузер сообщает другое состояние), при отклонённом запросе или без трека
камеры. Поэтому на устройстве, которое молча игнорирует запрос, подпись может сказать «вкл», хотя
ничего не горит. Не прячьте кнопку фонарика при `'unsupported'`: лучше покажите подпись. В
production эта функция не использовалась, поэтому считайте её экспериментальной, в production не
проверенной.

**5. Один цикл кадров, никогда не два.**
Симптом: после нескольких циклов пауза/продолжение или остановка/запуск одновременно работали
два-три цикла распознавания, и каждый из них распознавал каждый кадр.
Решение: цикл работает на `requestAnimationFrame`, его идентификатор хранится, а `pause()` и
`stop()` отменяют его через `cancelAnimationFrame`. Если кадр уже запланирован, повторное
планирование ничего не делает.

**6. Защита от повторов.**
Симптом: камера видит один и тот же код 30 раз в секунду; без защиты от повторов `onCode`
срабатывает снова и снова, и ваш сервер получает дубли.
Решение: по умолчанию ядро запоминает последний текст и не сообщает его повторно, пока вы не
вызовете `resetDedupe()` или `resume({ resetDedupe: true })`. Запоминается только последний код:
последовательность A, B, A сообщит A дважды. Есть два способа продолжить, и нужны оба:
- после **неудачной** отправки на вашей стороне вызывайте `resume()` без сброса. Код, который
  всё ещё перед камерой, не отправится повторно — иначе получился бы дубль, если первый запрос
  всё-таки дошёл до сервера;
- после **успешной** отправки покажите «уберите код из кадра», немного подождите и вызовите
  `resume({ resetDedupe: true })`. С этого момента принимается любой код, включая тот же самый.

Для страниц-считывателей (ссылки, складские этикетки), где один код показывают много раз,
задайте `dedupeMs`: тот же текст сообщается снова, если он не распознавался столько
миллисекунд. Окно скользящее: пока код остаётся в кадре, он молчит.

**7. Системные диалоги замораживают видео в Telegram.**
Симптом: в Telegram WebView после `alert()` или `confirm()` элемент `<video>` застывал на
последнем кадре и не оживал после закрытия диалога. Сканер выглядел мёртвым, и пользователю
приходилось заново открывать Mini App.
Решение: никогда не используйте системные диалоги (`alert`, `confirm`, `prompt`), пока открыт
сканер; рисуйте свой диалог на HTML, вызывайте `pause()` перед его показом и `resume()` после.
Для подстраховки `resume()` вызывает `video.play()`, если видео стоит на паузе. Если браузер
отклонит этот `play()`, вы получите `onError({ code: 'camera', message: 'video.play() rejected' })`:
покажите кнопку «нажмите, чтобы продолжить», которая вызывает `resume()` (см.
[Если `video.play()` отклонён](#если-videoplay-отклонён)).

**8. Остановка действительно освобождает камеру.**
Симптом: после того как пользователь ушёл со страницы, индикатор камеры продолжал гореть, и
пользователи резонно думали, что их всё ещё снимают.
Решение: `stop()` выключает фонарик (ждёт не дольше 300 мс, чтобы зависший фонарик не держал
камеру открытой), отменяет цикл кадров, вызывает `track.stop()` на каждом треке и отвязывает
поток от видео. Вызывайте его, когда закрывается экран сканера, и на `pagehide`.

**9. iOS нужны `playsinline` и `muted`.**
Симптом: на iOS без `playsinline` видео открывается на весь экран в системном плеере; без
`muted` оно не запускается само.
Решение: ядро ставит видео `playsinline`, `muted` и `autoplay` до подключения потока. Укажите
`playsinline muted` и в своей разметке.

**10. Telegram агрессивно кэширует скрипты.**
Симптом: вы выкладываете исправление, а пользователи внутри Telegram продолжают работать со
старым скриптом.
Решение: подключайте каждый скрипт с версией в query, `cam-scanner.js?v=0.1.0`, и поднимайте её
в каждом релизе.

## Ограничения

Чего эта библиотека сознательно не делает (как минимум в этой версии):

- **Нет npm-пакета, сборки через bundler и типов TypeScript.** Копируйте файлы. Возможно, они
  появятся позже.
- **Нет генерации QR**, нет распознавания фото из галереи, **один код на кадр** (если в кадре
  несколько кодов, сообщается один из них).
- **Нет серверной части.** Проверка чека в ФНС, хранение, дедупликация между пользователями —
  всё это на вашей стороне.
- **Нет Telegram-специфичных API** (`showScanQrPopup`, `initData`). Библиотека не знает, что она
  в Telegram; она просто работает в его WebView.
- **Нет нативного оптического зума**: зум цифровой (см. пункт 3 в разделе
  [Почему это работает](#почему-это-работает)).
- **Нет встроенного переключения камер**: вызовите `stop()` и создайте новый сканер с `deviceId`
  нужной камеры в `constraints`, в полном виде:
  `{ video: { deviceId: { exact: id }, width: { ideal: 1920 }, height: { ideal: 1080 } } }`. Ваши
  ограничения ЗАМЕНЯЮТ встроенные целиком; если такой запрос не удался, ядро молча переходит на
  свои встроенные мягкие ограничения, то есть на основную камеру. Новый сканер использует WASM,
  уже загруженный для его `wasmDir`.
- **Фонарик экспериментальный** и в production не проверен.
- **Защита от повторов помнит один код**, а не историю.

## Как добавить свой парсер

Парсер превращает сырой текст из `onCode` во что-то полезное. Контракт, которому следует и
`FnsReceipt`:

- глобальный объект с функцией `parse(text[, options])`;
- `parse` возвращает **объект**, если текст в его формате, и **`null`** в противном случае;
- он никогда не бросает исключений, не имеет побочных эффектов и не трогает DOM;
- по желанию `parse.lastError` хранит короткий код, объясняющий последний `null`.

Пример: парсер ссылок `geo:` (`geo:55.7558,37.6173`) в файле `src/parsers/geo-uri.js`:

```js
(function (root, factory) {
  var api = factory();
  if (typeof module === 'object' && module.exports) {
    module.exports = api;
  } else {
    root.GeoUri = api;
  }
})(typeof self !== 'undefined' ? self : this, function () {
  'use strict';

  var RE = /^geo:(-?\d+(?:\.\d+)?),(-?\d+(?:\.\d+)?)/i;

  function parse(text) {
    var m = typeof text === 'string' ? RE.exec(text) : null;
    if (!m) { parse.lastError = 'not-geo'; return null; }
    parse.lastError = null;
    return { lat: Number(m[1]), lon: Number(m[2]), raw: text };
  }

  parse.lastError = null;
  return { parse: parse };
});
```

Обёртка позволяет одному и тому же файлу работать как `<script>` в браузере и как `require()` в
Node, поэтому его можно тестировать через `node --test` без браузера. Дальше пробуйте парсеры по
очереди:

```js
onCode: function (text, type) {
  var receipt = FnsReceipt.parse(text);
  var place = receipt ? null : GeoUri.parse(text);
  if (receipt) { sendToMyBackend(receipt); }
  else if (place) { showOnMap(place.lat, place.lon); }
  else { showHint('Неизвестный код: ' + type); }
}
```

Пулл-реквесты с новыми парсерами приветствуются: добавьте файл, тесты в `test/` и строку в этот
раздел.
