# Протокол ручной проверки

Прогон на реальных устройствах (не эмуляторах). По итогам заполняется таблица платформ в разделе
Proof файлов `README.md` и `README.ru.md`: `works` / `does not work` / `not yet verified`
(в русском файле — «работает» / «не работает» / «ещё не проверено»). Провал строки публикацию не
блокирует: в README честно пишется «не работает», в issues заводится задача.

Демо: https://mad8fat.github.io/webview-qr-scanner/demo/

## Подготовка

1. **Mini App в Telegram.** В BotFather: `/mybots` → бот → Bot Settings → Menu Button →
   указать URL демо. Открывать Mini App кнопкой меню в чате с ботом.
2. **Встроенный браузер Telegram.** Отправить ссылку на демо в любой чат (например, в
   «Избранное») и нажать на неё. Это отдельная среда, не Mini App, поэтому проверяется
   отдельными строками.
3. **Что сканировать.** Под рукой: экран компьютера с QR-ссылкой (например, QR-код из раздела
   Demo в README), бумажный кассовый чек с QR-кодом, упаковка товара со штрихкодом EAN-13.
4. **Сброс разрешения камеры** (нужен перед строкой «отказ в доступе» и после неё): Chrome —
   значок слева от адреса → Разрешения → Камера → Сбросить; Telegram Android — Настройки
   Android → Приложения → Telegram → Разрешения → Камера.
5. **Как вызвать отказ `video.play()`.** Он случается не всегда. Попробовать: во время
   сканирования заблокировать экран и разблокировать; свернуть Telegram и вернуться; на iPhone —
   включить режим энергосбережения (он запрещает автозапуск видео). Если отказ не случился —
   записать в «Факт» «не воспроизвелось»: это не провал.

Столбец «Факт»: «ок», либо что произошло на самом деле (с секундами, текстом ошибки, скриншотом).

| Android Chrome | Камеру забрало другое приложение / трек завершён (во время сканирования открыть камеру в другом приложении, вернуться) | Статус ошибки камеры, кнопка Try again работает | |
| Android Chrome | Во время сканирования закрыть вкладку | Индикатор камеры в строке состояния гаснет | |
